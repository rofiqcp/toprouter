# TopRouter Fixes - June 25, 2026

## Problems Fixed

### 1. Login Issue
**Problem:** User tidak bisa login via HTTPS tunnel (ai.otomasi.app)

**Root Cause:** 
- `tunnelDashboardAccess` tidak di-set di settings table → default `false`
- Dashboard guard (`src/dashboardGuard.js`) memblokir akses via tunnel hostname tanpa `tunnelDashboardAccess=true`
- Cookie `Secure` flag di-set benar untuk HTTPS, tapi akses tetap di-redirect ke login

**Fix Applied:**
```sql
-- Set tunnelDashboardAccess + tunnelUrl
UPDATE settings 
SET data = jsonb_set(
  jsonb_set(data::jsonb, '{tunnelDashboardAccess}', 'true'),
  '{tunnelUrl}', '"https://ai.otomasi.app"'
)::text 
WHERE id=1;
```

**Verification:**
```bash
curl -s -c cookies.txt https://ai.otomasi.app/api/auth/login \
  -H 'Content-Type: application/json' -d '{"password":"123456"}'
# Returns: {"success":true}

curl -s -b cookies.txt https://ai.otomasi.app/dashboard
# Returns: 200 (dashboard HTML)
```

### 2. Image Edit & Video Models Not Showing
**Problem:** 
- `/v1/models/imageEdit` returned 404 "Unknown model kind"
- `/v1/models/video` returned 0 models
- Alibaba Media provider had 6 imageEdit + 32 video models but API didn't expose them

**Root Cause:**
- `MODEL_TYPE_TO_KIND` map in `/api/v1/models/route.js` missing `imageEdit` and `video` entries
- `KIND_SLUG_MAP` in `/api/v1/models/[kind]/route.js` missing `imageEdit` (only had `image-edit` with hyphen)

**Fix Applied:**
```javascript
// src/app/api/v1/models/route.js
const MODEL_TYPE_TO_KIND = {
  image: "image",
  imageEdit: "imageEdit",  // ← ADDED
  video: "video",          // ← ADDED
  tts: "tts",
  embedding: "embedding",
  stt: "stt",
  imageToText: "imageToText",
};

// src/app/api/v1/models/[kind]/route.js
const KIND_SLUG_MAP = {
  "image": ["image"],
  "imageEdit": ["imageEdit"],      // ← ADDED (camelCase)
  "image-edit": ["imageEdit"],     // ← kept for backward compat
  "video": ["video"],              // ← already existed
  // ...
};
```

**Verification:**
```bash
curl -s http://localhost:20128/v1/models/imageEdit \
  -H "Authorization: Bearer $API_KEY" | jq '.data | length'
# Output: 6 (qwen-image-edit models)

curl -s http://localhost:20128/v1/models/video \
  -H "Authorization: Bearer $API_KEY" | jq '.data | length'
# Output: 32 (wan2.x video models)
```

## Architecture

### Frontend-Backend Separation
```
User → Cloudflare Tunnel (ai.otomasi.app)
  ↓
Next.js Frontend (port 20128)
  ├─ Dashboard UI (React)
  └─ Rewrite /v1/* → Express Backend
       ↓
     Express Backend (port 3030)
       ├─ open-sse handlers
       └─ Streaming SSE
```

**Why separate?** 
Next.js 16 SSR shares event loop with SSE streaming → UI lag during long LLM responses. Separate Express process isolates streaming.

### Database Stack
```
Application Layer
  ├─ PostgreSQL (sirobo@localhost:5432/toprouter)
  │    ├─ Pool: 40 (frontend) + 20 (backend) = 60 total
  │    ├─ Max connections: 300
  │    └─ Tables: settings, providernodes, providerconnections, 
  │              combos, apikeys, kv, usageDaily, requestDetails
  │
  └─ Redis (localhost:6379)
       ├─ DB 0: Cache layer
       └─ DB 1: Queue
```
